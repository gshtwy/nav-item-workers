# 项目架构

## 总览

单个 Cloudflare Worker 承载全部后端逻辑，前端是原版 Vue 3 单页应用、构建后由 Workers Assets 托管；结构化数据存 D1，图片文件存 R2（可选）。没有独立服务器、没有常驻进程。

```
                        ┌──────────────────────────── Cloudflare ─────────────────────────────┐
                        │                                                                       │
  访客 ──── HTTPS ────► │  Worker（src/index.js，唯一入口 fetch）                               │
                        │    │                                                                  │
                        │    ├─ /api/wallpaper ─► 外部服务：Bing 官方接口 / NASA 官方图库        │
                        │    │                    （服务端解析后 302 跳真实图片地址）              │
                        │    │                                                                  │
                        │    ├─ /api/* ─────────► D1 数据库（绑定 DB）                           │
                        │    │                    菜单/卡片/广告/友链/用户/站点设置               │
                        │    │                                                                  │
                        │    ├─ /uploads/* ─────► R2 对象存储（绑定 BUCKET，可选）                │
                        │    │                    上传的配图与图库图片                            │
                        │    │                                                                  │
                        │    └─ 其它路径 ───────► Workers Assets（绑定 ASSETS）                  │
                        │                         web/dist 静态文件 + SPA 回退                  │
                        └───────────────────────────────────────────────────────────────────────┘
```

## 请求路由

Worker 入口按路径分发（顺序即代码顺序）：

| 路径 | 处理 | 说明 |
|---|---|---|
| `GET /api/wallpaper` | 背景解析 | `?src=nasa` 走 NASA 通道，否则 Bing 通道；解析出图片地址后 302 跳转（缓存 1 小时），任何失败回退本地 `/background.webp`，背景永不空白 |
| `/api/*` | JSON 接口 | 先过初始化（建表/播种快路径），再进接口路由；公开 GET 带 ETag 短缓存包装，写操作与后台接口需 JWT |
| `/uploads/*` | R2 读文件 | 从 BUCKET 按 key 取对象返回；无 BUCKET 时 404 |
| 其它 | ASSETS | 静态文件；未命中按 SPA 规则回退 `index.html` |

## 数据模型（D1，共 7 张表）

| 表 | 内容 | 备注 |
|---|---|---|
| `menus` | 一级栏目 | 含排序、图标 |
| `sub_menus` | 子栏目 | 外键挂 `menus` |
| `cards` | 导航卡片 | 挂栏目/子栏目；标题、链接、图标、描述 |
| `ads` | 左右广告位 | 图片+跳转链接 |
| `friends` | 友情链接 | |
| `users` | 后台用户 | 密码 PBKDF2-SHA256（10 万迭代、随机盐）存储 |
| `settings` | 站点设置 KV | 页脚版权、背景模式/地址、schema 版本标记 |

表结构见 `schema.sql`；Worker 首启自动建表并从 `src/seed.js` 播种默认菜单/卡片/友链与管理员账号，之后每次请求只走 `schema_version` 快路径判断，不再重复初始化。

## 鉴权

- `POST /api/login` 校验用户名/密码 → 签发 JWT（WebCrypto HMAC-SHA256，密钥为 Secret `JWT_SECRET`，有效期 2 小时）。
- 写接口与后台接口经统一 `requireAuth` 校验 `Authorization: Bearer <token>`。
- 图库接口多一条通道：请求头 `X-API-Key` 与 Secret `IMG_API_KEY` 常量时间比较通过也可（供外部程序当图床调用）；两条通道任一通过即可。
- 部署时更换 `JWT_SECRET` 会使全部已发令牌失效（密码不变），这是预期行为。

## 背景解析（本站的特色机制）

首页背景不写死图片，而是请求 `/api/wallpaper`，由 Worker 实时解析「当前应该显示哪张」再 302 跳转。前端请求地址带 `?d=日期-时段` 参数：302 响应本身有 1 小时缓存，带上时段参数后每跨一个时段就是新地址，天然穿透缓存，不会看到上个时段的旧图。

**时段划分**：北京时间一天分 4 段（0/6/12/18 点），函数 `bjNow()` 给出当前日期与段号，Bing 与 NASA 共用。

**Bing 通道**：Bing 官方 `HPImageArchive` 一天只出一张图，且实测各国市场多数日子是同一张。轮换策略（办法三）：
1. 今日中国版（zh-CN）固定为段 1（6–12 点）的锚图；
2. 其余段按优先级凑图：今日各国市场（中/美/日/英）→ 前 1 天各国 → ……最多回溯 6 天；
3. 按图片标识（URL 中的 `OHR.<名称>`）去重，同图只占一位；
4. 收藏按钮与显示走同一个 `fetchBingSlot()`，保证存下来的就是正在显示的那张。

**NASA 通道**（`?src=nasa`）：
1. 主通道是 NASA 官方图库搜索（images-api，免 key）：按「日期+段号」种子在 8 个天文主题词间轮换并挑选条目；
2. 内容过滤：标题/说明必须命中天文词、且不含地面纪实类词（发射、发布会、设施、人物等），只留纯太空图；
3. 图片变体逐个探测可用性（`~medium` → `~orig` → `~small`）：变体因图而异，盲选高清版会遇到不存在而 403；
4. 主通道失败 → 备用 APOD 接口（需 `NASA_API_KEY`，过滤占位图、可回溯 7 天找可用图）→ 再失败回退本地图。

**背景收藏**：`POST /api/background/collect`（需登录）在服务端按同一套逻辑解析出当前背景图地址、抓取原图字节存进 R2 的 `img/<日期>/` 目录（与图库上传同一命名规则），图库管理页立即可见。无 R2 时返回 501。

## 图库（R2 布局）

- 栏目/卡片/广告配图：`POST /api/upload` 存 R2 根目录，文件名 `时间戳.扩展名`（沿原版规则），经 `/uploads/<文件名>` 访问。
- 图库图片：`POST /api/img/upload` 存 `img/<北京时间日期>/<时间戳>-<随机>.<扩展名>`，只收图片类型、单张 ≤ 20MB；列表/删除为 `/api/img/list`、`/api/img/delete?key=`。
- BUCKET 未绑定时以上接口全部 501 明确提示，`/uploads/*` 为 404——这是「无 R2 部署」的预期形态，其余功能不受影响。

## 缓存策略

| 对象 | 策略 |
|---|---|
| 公开 GET 接口（菜单/卡片/广告/友链/版权/背景设置） | ETag + `Cache-Control: max-age=30, s-maxage=120`；后台请求带时间戳参数自动绕开 |
| 壁纸 302 跳转 | `max-age=3600`；配合前端「日期-时段」参数保证跨段新鲜 |
| `/api/bootstrap` | 与公开 GET 同策略；一次批量查询返回首页所需的菜单+首栏卡片+广告+友链+版权+背景 |

## 代码组织

Worker 是单个文件 `src/index.js`（移植约束：便于 Dashboard 手动部署时整段粘贴），内部按段组织：工具（时间/密码/JWT）→ 初始化与播种 → 背景解析（Bing/NASA）→ 接口路由（公开/鉴权/图库/收藏）→ 上传读取。默认数据独立在 `src/seed.js`，wrangler 部署时与主文件一起打包（模块导入）；Dashboard 手动部署需把 seed 内容内联，见部署手册的手动路线说明。

前端 `web/` 为原版 Vue 3 工程，仅动了接口层与少量页面：`api.js` 增加 bootstrap、背景、图库、收藏等新接口；视图层新增图库管理页，背景设置页含四种模式与收藏按钮，页脚组件读后台版权设置渲染。
