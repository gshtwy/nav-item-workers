# 部署手册

从零把本站部署到你自己的 Cloudflare 账号。两条路线任选：

- **路线 A：wrangler 命令行**（推荐，步骤少、可重复）
- **路线 B：Dashboard 手动**（不装命令行，全部在网页后台点出来）

每条路线都分两种情况写：**有 R2**（图片功能全开）和**无 R2**（跳过图片存储，站点照常运行）。先想清楚要不要 R2：

| | 有 R2 | 无 R2 |
|---|---|---|
| 首页/后台/背景轮换 | ✅ | ✅ |
| 后台上传配图（栏目/卡片/广告图） | ✅ | ❌（填外链图片地址代替） |
| 图库管理 + 图床 API | ✅ | ❌（接口返回 501 提示） |
| 背景图一键收藏到图库 | ✅ | ❌ |
| 额外开通步骤 | 需在 Dashboard 同意 R2 条款（免费额度 10GB 起） | 无 |

先按无 R2 部署、以后再补 R2 也完全可以：建桶 → 加绑定 → 重新部署，数据不用动。

## 前置条件

- 一个 Cloudflare 账号（免费计划即可）
- 路线 A 还需要：Node.js 18+、能联网的终端
- 建议提前想好：管理员密码、一条长随机串作 JWT 密钥（`openssl rand -hex 32` 生成）

## 路线 A：wrangler 命令行

### A1. 拉代码并构建前端

```bash
git clone <本仓库地址> nav-item-workers
cd nav-item-workers
cd web && npm install && npm run build && cd ..
```

构建产物在 `web/dist`，部署时由 ASSETS 绑定托管。**没构建就部署，线上会没有前端页面。**

### A2. 登录并创建 D1

```bash
npx wrangler login
npx wrangler d1 create nav-item-workers-db --location apac
```

`--location` 按你的主要访客选：`apac`（亚太）/ `weur`（西欧）/ `eeur`（东欧）/ `enam`（北美东）等；D1 是单主库，选近的延迟低很多。命令会输出 `database_id`，把它填进 `wrangler.toml` 的 `[[d1_databases]]` 段（替换 `YOUR_D1_DATABASE_ID`）。

表结构不用手动建：Worker 首次请求会自动建表并播种默认数据。

### A3.（仅有 R2 时）创建 R2 桶

第一次用 R2 要先在 Dashboard 开通：左侧 **R2 对象存储** → 按提示同意条款（API/命令行代替不了这一步，没同意会报 `10042` 类错误）。然后：

```bash
npx wrangler r2 bucket create nav-item-workers-uploads
```

再把 `wrangler.toml` 末尾的 R2 段取消注释：

```toml
[[r2_buckets]]
binding = "BUCKET"
bucket_name = "nav-item-workers-uploads"   # 换成你的桶名
```

无 R2 就保持注释状态，什么都不用做。

### A4. 设置 Secret

必需两个（部署前或部署后设置都可以，设置后自动生效）：

```bash
npx wrangler secret put ADMIN_PASSWORD   # 后台管理员初始密码，按提示输入
npx wrangler secret put JWT_SECRET       # 粘贴第 0 步生成的长随机串
```

可选两个：

```bash
npx wrangler secret put IMG_API_KEY    # 只有想用图床 API 时才需要
npx wrangler secret put NASA_API_KEY   # NASA 备用通道 Key，在 https://api.nasa.gov 免费申请；不设则 NASA 背景只有主通道
```

各参数的详细说明见 [配置参数](配置参数.md)。

### A5. 部署

```bash
npx wrangler deploy
```

输出里会给出 `https://nav-item-workers.<你的子域>.workers.dev` 地址。

### A6. 验收

```bash
curl https://nav-item-workers.<你的子域>.workers.dev/api/health
# 期望：{"ok":true,"version":"x.y.z-workers"}
```

浏览器打开首页应能看到导航页；打开 `/admin` 用 `admin` + 你设的 ADMIN_PASSWORD 登录，进后台先到「用户管理」**把初始密码改成你自己的密码**（改后以新密码为准）。

## 路线 B：Dashboard 手动部署（点选版）

全程在 https://dash.cloudflare.com 网页后台操作，不用命令行。下面每一步都是实际点击顺序；先把 B1–B3 的准备做完，再建 Worker。

### B1. 建 D1 数据库

1. 登录 Dashboard，左侧菜单点 **存储和数据库 → D1 SQL 数据库**。
2. 点 **创建数据库**，名称填 `nav-item-workers-db`；位置（Location）按主要访客就近选（如亚太选亚太），点创建。
3. 建好后点进该数据库详情页，记下 **数据库 ID**（一串 UUID，后面绑定时要核对）。表不用建，Worker 首次访问会自动建表并填默认数据。

### B2.（仅有 R2 时）开通 R2 并建桶

1. 左侧菜单点 **R2 对象存储**。第一次进入会让先同意 R2 条款并开通（这一步只能在网页上做，API 代替不了；没开通就建桶会报 `10042`）。
2. 开通后点 **创建存储桶**，名称填 `nav-item-workers-uploads`，位置默认即可，点创建。
3. 无 R2 就跳过本步，后面不绑 BUCKET 即可（图片上传/图库/背景收藏不可用，其余正常）。

### B3. 在本地准备两样东西

**（1）单文件 Worker 代码**（Dashboard 编辑器只能粘一个文件，要先把两份源码合成一份）：

1. 打开 `src/seed.js`，把第一行附近的 `export const SEED` 改成 `const SEED`（只删 `export ` 五个字符，其余不动），另存内容备用。
2. 打开 `src/index.js`，找到这一行并整行删掉：`import { SEED } from './seed.js';`
3. 把第 1 步改好的 seed.js **全文**粘贴到刚刚删掉 import 的位置。
4. 保存为一个新文件（比如 `worker-单文件.js`）。有 Node 环境的话先跑 `node --check worker-单文件.js` 确认语法通过再往下走。

**（2）前端文件**：在 `web/` 目录执行 `npm install && npm run build`，得到 `web/dist` 文件夹，B6 要上传它。没有本地 Node 环境也可以先跳过前端、只部署接口，之后再补（首页会打不开，后台接口可用）。

### B4. 建 Worker 并粘贴代码

1. 左侧菜单 **Workers 和 Pages → 创建应用程序 → 创建 Worker**，名称填 `nav-item-workers`，点 **部署**（先部署一个占位版本）。
2. 部署完点 **编辑代码**，进入在线编辑器；把编辑器里的占位代码**全选删除**。
3. 把 B3 合成的单文件代码**整段粘贴**进去，点右上角 **部署**，等它提示部署成功。

### B5. 绑定 D1（和 R2）

1. 回到该 Worker 的页面，点 **设置 → 绑定 → 添加**。
2. 选 **D1 数据库**：变量名称填 `DB`（必须大写、不能改名），数据库选 B1 建的 `nav-item-workers-db`，保存。
3.（仅有 R2 时）再 **添加** 一个 **R2 存储桶** 绑定：变量名称填 `BUCKET`，桶选 B2 的 `nav-item-workers-uploads`，保存。
4. 绑定保存后 Worker 会自动重新部署一次，属正常现象。

### B6. 上传前端静态文件（Assets）

1. 在该 Worker 的 **设置** 里找到 **资产 / Assets**（不同控制台版本入口位置略有差异），把 B3 构建好的 `web/dist` 里的全部文件上传。
2. 确认资产的绑定名是 `ASSETS`，且 `/api/*` 与 `/uploads/*` 两条路径设为**优先运行 Worker**（run_worker_first），否则接口和图片会被当成静态文件。
3. 如果你的控制台版本没有资产上传入口：改用路线 A 的命令 `npx wrangler deploy` 发一次即可（wrangler.toml 里把 D1 的 id 填成 B1 的那个，其余配置别动），效果一样，后续仍可在 Dashboard 管。

### B7. 设置环境变量与机密（关键一步，逐个添加）

位置：该 Worker 的 **设置 → 变量和机密 → 添加**。变量分两类：**文本**（明文变量）和**机密**（Secret，保存后看不见值）。逐个按下面添加，名称必须一字不差：

| # | 类型 | 名称 | 填什么 | 必需 |
|---|---|---|---|---|
| 1 | 文本 | `ADMIN_USERNAME` | `admin`（想改管理员用户名就填别的） | 可选，不设默认 admin |
| 2 | 机密 | `ADMIN_PASSWORD` | 你定的后台初始密码（自己记好） | **必需** |
| 3 | 机密 | `JWT_SECRET` | 长随机串，32 位以上，如 `openssl rand -hex 32` 生成的一串，或密码生成器出的一长串 | **必需** |
| 4 | 机密 | `IMG_API_KEY` | 另一条长随机串；只有打算用图床 API 时才加 | 可选 |
| 5 | 机密 | `NASA_API_KEY` | 在 https://api.nasa.gov 免费申请、发到你邮箱的那把 Key；不加则 NASA 背景只有主通道 | 可选 |

添加时的注意点：

- 每加完一个点**保存/部署**让它生效；机密保存后页面上只显示名字、看不到值，这是正常的，想改只能重新填一遍覆盖。
- **在 Dashboard 里保存变量是整页全量提交**：编辑时页面上已有的变量不要误删，漏了哪个，线上就丢哪个。改之前先把现有 5 项对一遍。
- `ADMIN_PASSWORD` 只是**初始密码**：第一次登录后在后台「用户管理」改掉，之后以新密码为准，再改这个机密也不会影响已改的密码。
- `JWT_SECRET` 一旦更换，之前登录的令牌全部失效、要重新登录一次，属正常现象，密码不受影响。
- 各变量的完整说明见 [配置参数](配置参数.md)。

### B8. 打开访问地址（workers.dev）

1. 在该 Worker 的 **设置 → 域和路由** 里，确认 **workers.dev 已启用**；没启用就打开它（经某些方式建的 Worker 默认是关的，关着访问会报 `1042`）。
2. 页面上会显示地址 `https://nav-item-workers.<你的子域>.workers.dev`，这就是你的站点了。有自己的域名也可以在这里 **添加自定义域**。

### B9. 验收

1. 浏览器打开站点地址：首页出现导航页 ✅
2. 打开 `https://你的地址/api/health`：返回 `{"ok":true,"version":"..."}` ✅
3. 打开 `https://你的地址/admin`：用 `admin` + B7 设的初始密码能登录 ✅，登录后**第一件事去「用户管理」改密码**。
4.（有 R2 时）在后台「图库管理」上传一张图，能出现在列表里且能打开 ✅；无 R2 时图库页提示「R2 未绑定」属预期。

## 部署后建议

1. **改管理员密码**：后台「用户管理」里改，改后保存在 D1、与 Secret 里的初始密码脱钩。
2. **绑自定义域名**（可选）：Worker 设置 → 域和路由 → 添加自定义域，比 workers.dev 地址更适合长期使用。
3. **改默认内容**：默认菜单/卡片是原版演示数据，在后台逐个换成你自己的；页脚版权在后台「版权所有」栏改。

## 升级（更新代码后重新部署）

- 路线 A：拉新代码 → `cd web && npm run build`（前端有改动时）→ `npx wrangler deploy`。
- 路线 B：重新合成单文件 → 编辑器粘贴替换 → 部署；前端有改动时重新上传 dist。
- **注意**：部署不会动 D1 数据与 Secret；但如果这次部署同时换了 `JWT_SECRET`，后台需要重新登录一次（正常现象）。用 wrangler 部署时不要在 wrangler.toml 里写明文密钥，Secret 只用 `wrangler secret put` 管理。

## 常见问题

**Q：打开 workers.dev 地址报 1042 / 打不开？**
Worker 的 workers.dev 路由没启用。Dashboard → 该 Worker → 设置 → 域和路由 → 把 workers.dev 打开。

**Q：创建 R2 桶报 10042？**
R2 没开通。先去 Dashboard 的 R2 页面同意条款，命令行/API 代替不了。

**Q：后台登录提示 401 / 密码不对？**
先确认用的是哪个密码：从没在后台改过 → 是 Secret `ADMIN_PASSWORD` 的值；在后台改过 → 以改后的为准（Secret 改了也不生效）。JWT_SECRET 被换过也会让旧登录态失效，重新登录即可。

**Q：背景图不换新 / 还是旧图？**
壁纸跳转带 1 小时缓存，部署或切模式后旧图可能残留到缓存过期；强刷（Ctrl+Shift+R）或等一小时即恢复。跨时段（0/6/12/18 点）会自动换新地址，不受影响。

**Q：图片上传/图库返回 501「R2 未绑定」？**
这是无 R2 部署的预期提示。想开启：建 R2 桶 → wrangler.toml 取消 R2 段注释（或 Dashboard 加 BUCKET 绑定）→ 重新部署。

**Q：NASA 背景偶尔回退到本地图？**
NASA 图库接口或当日图不可用时的兜底链（主通道 → APOD 备用 → 本地）走到了最后一步，属正常保护；稍后自动恢复。APOD 备用需要 `NASA_API_KEY`，没设时备用段跳过。

**Q：D1 数据想备份/迁移？**
`npx wrangler d1 export nav-item-workers-db --remote -o backup.sql` 导出；恢复用 `wrangler d1 execute --file`。图片文件在 R2 里，用 Dashboard 或 S3 兼容工具单独备份。
