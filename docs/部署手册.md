# 部署手册

从零把本站部署到你自己的 Cloudflare 账号。两条路线任选：

- **路线 A：wrangler 命令行**（推荐，步骤少、可重复）
- **路线 B：Dashboard 手动**（不装命令行，全部在网页后台点出来）

每条路线都分两种情况写：**有 R2**（图片功能全开）和**无 R2**（跳过图片存储，站点照常运行）。先想清楚要不要 R2：

| | 有 R2 | 无 R2 |
|---|---|---|
| 首页/后台/背景轮换 | ✅ | ✅ |
| 后台上传配图（栏目/卡片/广告图） | ✅ | ❌（填外链图片地址代替） |
| 图库管理 + 图床 API | ✅ | ❌（接口返回 501 提示） |
| 背景图一键收藏到图库 | ✅ | ❌ |
| 额外开通步骤 | 需在 Dashboard 同意 R2 条款（免费额度 10GB 起） | 无 |

先按无 R2 部署、以后再补 R2 也完全可以：建桶 → 加绑定 → 重新部署，数据不用动。

## 前置条件

- 一个 Cloudflare 账号（免费计划即可）
- 路线 A 还需要：Node.js 18+、能联网的终端
- 建议提前想好：管理员密码、一条长随机串作 JWT 密钥（`openssl rand -hex 32` 生成）

## 路线 A：wrangler 命令行

### A1. 拉代码并构建前端

```bash
git clone <本仓库地址> nav-item-workers
cd nav-item-workers
cd web && npm install && npm run build && cd ..
```

构建产物在 `web/dist`，部署时由 ASSETS 绑定托管。**没构建就部署，线上会没有前端页面。**

### A2. 登录并创建 D1

```bash
npx wrangler login
npx wrangler d1 create nav-item-workers-db --location apac
```

`--location` 按你的主要访客选：`apac`（亚太）/ `weur`（西欧）/ `eeur`（东欧）/ `enam`（北美东）等；D1 是单主库，选近的延迟低很多。命令会输出 `database_id`，把它填进 `wrangler.toml` 的 `[[d1_databases]]` 段（替换 `YOUR_D1_DATABASE_ID`）。

表结构不用手动建：Worker 首次请求会自动建表并播种默认数据。

### A3.（仅有 R2 时）创建 R2 桶

第一次用 R2 要先在 Dashboard 开通：左侧 **R2 对象存储** → 按提示同意条款（API/命令行代替不了这一步，没同意会报 `10042` 类错误）。然后：

```bash
npx wrangler r2 bucket create nav-item-workers-uploads
```

再把 `wrangler.toml` 末尾的 R2 段取消注释：

```toml
[[r2_buckets]]
binding = "BUCKET"
bucket_name = "nav-item-workers-uploads"   # 换成你的桶名
```

无 R2 就保持注释状态，什么都不用做。

### A4. 设置 Secret

必需两个（部署前或部署后设置都可以，设置后自动生效）：

```bash
npx wrangler secret put ADMIN_PASSWORD   # 后台管理员初始密码，按提示输入
npx wrangler secret put JWT_SECRET       # 粘贴第 0 步生成的长随机串
```

可选两个：

```bash
npx wrangler secret put IMG_API_KEY    # 只有想用图床 API 时才需要
npx wrangler secret put NASA_API_KEY   # NASA 备用通道 Key，在 https://api.nasa.gov 免费申请；不设则 NASA 背景只有主通道
```

各参数的详细说明见 [配置参数](配置参数.md)。

### A5. 部署

```bash
npx wrangler deploy
```

输出里会给出 `https://nav-item-workers.<你的子域>.workers.dev` 地址。

### A6. 验收

```bash
curl https://nav-item-workers.<你的子域>.workers.dev/api/health
# 期望：{"ok":true,"version":"x.y.z-workers"}
```

浏览器打开首页应能看到导航页；打开 `/admin` 用 `admin` + 你设的 ADMIN_PASSWORD 登录，进后台先到「用户管理」**把初始密码改成你自己的密码**（改后以新密码为准）。

## 路线 B：Dashboard 手动部署

全程在 https://dash.cloudflare.com 网页后台操作。

### B1. 建 D1

左侧 **存储和数据库 → D1 SQL 数据库 → 创建数据库**，名字填 `nav-item-workers-db`，位置按访客区域选。建好后记下它的 **数据库 ID**（详情页可见）。表不用建，首启自动建。

### B2.（仅有 R2 时）建 R2 桶

左侧 **R2 对象存储** → 首次进入按提示同意条款 → **创建存储桶**，名字填 `nav-item-workers-uploads`。无 R2 跳过本步。

### B3. 准备单文件代码

Worker 主代码在 `src/index.js`，它 `import` 了 `src/seed.js` 的默认数据。Dashboard 编辑器是单文件粘贴，需要先把两份合成一份：

1. 把 `seed.js` 开头的 `export const SEED` 改成 `const SEED`；
2. 把 `index.js` 里 `import { SEED } from './seed.js';` 这一行，替换为改好的 seed.js 全文；
3. 合成后的文件就是部署用的单文件代码（本地先 `node --check` 确认语法没问题）。

前端静态文件：在本地把 `web/` 构建出 `web/dist`（需要 Node.js 环境执行一次 `npm install && npm run build`），B5 用。

### B4. 建 Worker 并粘贴代码

**Workers 和 Pages → 创建 → Worker → 从 Hello World 开始**，名字填 `nav-item-workers`，部署一次占位版本；然后 **编辑代码**，把占位代码整段换成 B3 的单文件代码，保存并部署。

### B5. 绑定资源与变量

进入该 Worker 的 **设置 → 绑定**，逐个添加：

| 类型 | 名称 | 值 |
|---|---|---|
| D1 数据库 | `DB` | 选 B1 建的库 |
| R2 存储桶（仅有 R2 时） | `BUCKET` | 选 B2 建的桶 |

**设置 → 变量和机密** 里添加：

| 类型 | 名称 | 值 |
|---|---|---|
| 文本 | `ADMIN_USERNAME` | `admin` |
| 机密 | `ADMIN_PASSWORD` | 你的管理员初始密码 |
| 机密 | `JWT_SECRET` | 长随机串（见前置条件） |
| 机密（可选） | `IMG_API_KEY` | 图床 API 密钥，想用才加 |
| 机密（可选） | `NASA_API_KEY` | NASA 备用通道 Key，想用才加 |

前端静态资源：在该 Worker 的 **设置 → 资产**（不同控制台版本入口名略有差异）上传 B3 构建好的 `web/dist` 全部文件，并确认资产绑定名为 `ASSETS`、且 `/api/*`、`/uploads/*` 优先跑 Worker（run_worker_first）。如果你的控制台没有资产上传入口，退一步用路线 A 的 `npx wrangler deploy` 只发一次（配置在 Dashboard 里已经齐了，wrangler.toml 里填上同一个 D1 id 即可），效果相同。

### B6. 打开访问地址并验收

**设置 → 域和路由** 里确认 `workers.dev` 已启用（经某些方式创建的 Worker 它默认是关的，关着会报 `1042` 打不开）。访问 `https://nav-item-workers.<你的子域>.workers.dev`：

- 首页出现导航页 ✅
- `/api/health` 返回 `{"ok":true,...}` ✅
- `/admin` 能用初始密码登录 ✅ → 立刻在「用户管理」改掉初始密码

## 部署后建议

1. **改管理员密码**：后台「用户管理」里改，改后保存在 D1、与 Secret 里的初始密码脱钩。
2. **绑自定义域名**（可选）：Worker 设置 → 域和路由 → 添加自定义域，比 workers.dev 地址更适合长期使用。
3. **改默认内容**：默认菜单/卡片是原版演示数据，在后台逐个换成你自己的；页脚版权在后台「版权所有」栏改。

## 升级（更新代码后重新部署）

- 路线 A：拉新代码 → `cd web && npm run build`（前端有改动时）→ `npx wrangler deploy`。
- 路线 B：重新合成单文件 → 编辑器粘贴替换 → 部署；前端有改动时重新上传 dist。
- **注意**：部署不会动 D1 数据与 Secret；但如果这次部署同时换了 `JWT_SECRET`，后台需要重新登录一次（正常现象）。用 wrangler 部署时不要在 wrangler.toml 里写明文密钥，Secret 只用 `wrangler secret put` 管理。

## 常见问题

**Q：打开 workers.dev 地址报 1042 / 打不开？**
Worker 的 workers.dev 路由没启用。Dashboard → 该 Worker → 设置 → 域和路由 → 把 workers.dev 打开。

**Q：创建 R2 桶报 10042？**
R2 没开通。先去 Dashboard 的 R2 页面同意条款，命令行/API 代替不了。

**Q：后台登录提示 401 / 密码不对？**
先确认用的是哪个密码：从没在后台改过 → 是 Secret `ADMIN_PASSWORD` 的值；在后台改过 → 以改后的为准（Secret 改了也不生效）。JWT_SECRET 被换过也会让旧登录态失效，重新登录即可。

**Q：背景图不换新 / 还是旧图？**
壁纸跳转带 1 小时缓存，部署或切模式后旧图可能残留到缓存过期；强刷（Ctrl+Shift+R）或等一小时即恢复。跨时段（0/6/12/18 点）会自动换新地址，不受影响。

**Q：图片上传/图库返回 501「R2 未绑定」？**
这是无 R2 部署的预期提示。想开启：建 R2 桶 → wrangler.toml 取消 R2 段注释（或 Dashboard 加 BUCKET 绑定）→ 重新部署。

**Q：NASA 背景偶尔回退到本地图？**
NASA 图库接口或当日图不可用时的兜底链（主通道 → APOD 备用 → 本地）走到了最后一步，属正常保护；稍后自动恢复。APOD 备用需要 `NASA_API_KEY`，没设时备用段跳过。

**Q：D1 数据想备份/迁移？**
`npx wrangler d1 export nav-item-workers-db --remote -o backup.sql` 导出；恢复用 `wrangler d1 execute --file`。图片文件在 R2 里，用 Dashboard 或 S3 兼容工具单独备份。
