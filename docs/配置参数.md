# 配置参数

本项目没有 `.env` 式的配置文件：运行参数由 Cloudflare 的**绑定（Bindings）**、**明文变量（Vars）**与**机密（Secrets）**三部分组成，在 `wrangler.toml` 里声明绑定、用 `wrangler secret put` 或 Dashboard 设置机密。全部参数如下。

## 总表

| 名称 | 类型 | 必需 | 用途 | 没有它会怎样 |
|---|---|---|---|---|
| `DB` | D1 绑定 | **必需** | 全部业务数据（菜单/卡片/用户/设置） | 站点不可用 |
| `ASSETS` | 静态资源绑定 | **必需** | 托管前端 `web/dist` | 前端页面打不开 |
| `BUCKET` | R2 绑定 | 可选 | 图片文件存储（上传/图库/背景收藏） | 三个图片功能返回 501 明确提示，其余功能正常（见下文） |
| `ADMIN_USERNAME` | 明文变量 | 可选 | 后台管理员用户名，默认 `admin` | 用默认值 `admin` |
| `ADMIN_PASSWORD` | Secret | **必需** | 后台管理员**初始**密码（首启播种到 users 表） | 无法播种管理员、登录不了后台 |
| `JWT_SECRET` | Secret | **必需** | 登录令牌（JWT HS256）签名密钥 | 登录接口不可用 |
| `IMG_API_KEY` | Secret | 可选 | 图库 API 的 `X-API-Key` 鉴权密钥 | 后台图库页照常（走登录令牌）；只是外部程序无法用 API 方式调图库 |
| `NASA_API_KEY` | Secret | 可选 | NASA APOD 备用通道的官方 API Key | NASA 背景主通道（官方图库）免 key 照常工作；仅备用通道不可用 |

## 逐项说明

### DB（D1 绑定，必需）

- 在 `wrangler.toml` 的 `[[d1_databases]]` 段声明：`binding = "DB"`、`database_name`、`database_id` 换成你自己创建的 D1 的 id。
- 表结构由 Worker 首次请求时自动创建并播种，**不需要手工执行 `schema.sql`**（该文件仅供参考/手动排障）。

### ASSETS（静态资源绑定，必需）

- 在 `wrangler.toml` 的 `[assets]` 段声明，`directory = "./web/dist"`，部署前先在 `web/` 下 `npm run build` 生成。
- 本项目的 assets 配置带 `run_worker_first = ["/api/*", "/uploads/*"]`：这两个前缀先进 Worker，其余路径直接发静态文件，SPA 回退由 `not_found_handling = "single-page-application"` 处理。**不要删改这两项**，删了会出现接口被当成页面、图片 404 等问题。

### BUCKET（R2 绑定，可选）

- 开通了 R2 才绑：`wrangler.toml` 里 R2 段默认是注释状态，取消注释并把 `bucket_name` 换成你的桶名即可。
- **不绑 BUCKET 的影响**（代码已做优雅降级，均返回 `501` + 中文提示，不会 500 报错）：
  - `POST /api/upload`（栏目/卡片/广告配图上传）不可用 → 图标直接填外链图片地址
  - 图库管理整套（`/api/img/*`）不可用
  - 背景图收藏（`POST /api/background/collect`）不可用
  - `GET /uploads/*` 一律 404（本来就没有文件）
- 后续想补 R2：建桶 → 取消 wrangler.toml 注释 → 重新 `wrangler deploy` 即可，数据不用迁移。

### ADMIN_USERNAME（明文变量，可选）

- 默认 `admin`。写在 `wrangler.toml` 的 `[vars]` 段。
- 只在**首启播种管理员账号时**使用；库里已有用户后改它不会改已存在的账号名。

### ADMIN_PASSWORD（Secret，必需）

- 后台管理员**初始密码**。首启时与 `ADMIN_USERNAME` 一起播种进 users 表（PBKDF2-SHA256、10 万次迭代存储）。
- 之后在后台「用户管理」里改的密码写在 D1 里、**以 D1 为准**；再改这个 Secret 不会影响已播种的账号（除非删库重播种）。
- 设置：`npx wrangler secret put ADMIN_PASSWORD` 后按提示输入；或在 Dashboard 的 Worker 设置 → 变量和机密里添加（类型选「机密」）。

### JWT_SECRET（Secret，必需）

- 登录令牌签名密钥，任意足够长的随机字符串即可，例如 64 位十六进制：
  - macOS/Linux：`openssl rand -hex 32`
- 设置：`npx wrangler secret put JWT_SECRET`。
- **每次更换它，已登录的令牌立即全部失效**，需要重新登录；管理员密码不受影响。

### IMG_API_KEY（Secret，可选）

- 给「图库当图床」场景用：外部程序调用 `POST /api/img/upload`、`GET /api/img/list`、`DELETE /api/img/delete?key=` 时，请求头带 `X-API-Key: <你的密钥>` 即可，不必登录后台。
- 后台图库管理页走的是登录令牌，**不依赖这个密钥**；不打算给外部程序用图库就可以不设。
- 任意长随机字符串，生成方法同 JWT_SECRET。

### NASA_API_KEY（Secret，可选）

- NASA 背景的**备用通道**（APOD 每日天文图）需要官方 API Key，在 https://api.nasa.gov 免费申请（填邮箱即发到邮箱）。
- 主通道是 NASA 官方图库搜索接口，免 key；只有主通道失败时才落到 APOD。**不设这个密钥 NASA 背景照常工作**，只是少一层备用。
- 注意：APOD 从部分机房网络访问会被 NASA 降级返回占位图，代码已过滤占位图并自动回退前几天的图，最终仍不行会回退到主通道/本地图。

## 本地开发变量

本地 `wrangler dev` 不读线上 Secret，读项目根目录的 `.dev.vars` 文件（已在仓库附 `.dev.vars.example` 示例）：

```
ADMIN_PASSWORD=本地测试密码
JWT_SECRET=本地测试随机串
IMG_API_KEY=本地测试图库密钥
NASA_API_KEY=本地测试可留空
```

`.dev.vars` 已列入 `.gitignore` 思路的敏感文件，**不要提交到仓库**。

## 运行时设置（不用部署、在后台改）

以下设置存在 D1 的 `settings` 表里，后台页面维护、保存即生效，**不属于部署参数**：

| 设置 | 在哪改 | 说明 |
|---|---|---|
| 页脚版权（年份/主体/Powered 文案与链接） | 后台「版权所有」 | 首页页脚实时读取 |
| 背景模式与自定义图地址 | 后台「背景设置」 | `bing` / `nasa` / `local` / `custom` 四选一 |
| 管理员密码 | 后台「用户管理」 | 改的是 D1 里的账号，与 ADMIN_PASSWORD Secret 脱钩（见上文） |
